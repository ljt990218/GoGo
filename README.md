# GoGo · 围棋局面分析助手

GoGo 是本机运行的围棋复盘网页应用，使用 Vue 3、TypeScript、Vite、FastAPI 和 IndexedDB。导入 SGF 棋谱后，可浏览局面、调用 KataGo 获取候选点，再通过 DeepSeek 协议接口生成中文解释。棋谱和实战分析保存在当前浏览器，支持从任意局面自由试下。

需求背景见 [MVP-PRD.md](./MVP-PRD.md)，当前使用方式和实现边界以本文为准。

## 快速启动

需要 Node.js >=22.12、npm、Python >=3.11 和 uv。分析还需要可用的 KataGo 程序及权重，或兼容的本机 KataGo HTTP 服务；中文解释需要配置 AI 接口密钥。

在项目根目录执行：

```sh
npm run dev
```

在 Google Chrome 打开 [GoGo](http://127.0.0.1:5178)。

- 前端固定使用 `127.0.0.1:5178`，后端固定使用 `127.0.0.1:8008`。
- 首次启动缺少前端依赖时自动执行 `npm ci`，后端通过 `uv run --frozen` 同步锁定依赖。
- 启动前检查两个端口，端口不可用时退出，不自动换端口或停止已有服务。
- 按 Ctrl+C 同时关闭两端，任一服务退出也会停止另一服务。
- 启动不会自动发起 KataGo 分析或 AI 请求。

请保留已有的 `backend/.env` 和 `backend/settings.json`。新机器需要重新配置密钥及引擎路径，不要用示例覆盖已有配置。

### 分别启动

在项目根目录启动后端：

```sh
cd backend
uv sync --frozen
uv run --frozen python run.py
```

另开终端，在项目根目录启动前端：

```sh
npm ci
npm run dev:frontend
```

后端入口启用 `backend/app` 下 Python 源码的热更新。前端开发和预览均将 `/api` 转发到后端。

项目还提供 `npm run build` 和 `npm run preview`，分别用于构建前端和预览构建结果。预览固定使用 5178，仍需单独启动后端。

## 分析配置

首页展开“项目分析配置”，或点击顶部“分析设置”图标。首页与棋谱页共用配置，保存后用于后续分析，已有分析结果保持原样。

| 配置项 | 默认值或行为 |
| --- | --- |
| AI 分析 URL | `https://api.deepseek.com/chat/completions`，填写完整接口地址 |
| API 密钥 | 留空保留现有密钥 |
| 最大 token 数 | 1000，正整数 |
| KataGo 程序与权重路径 | 同时填写绝对路径，或同时留空 |
| 每手分析深度（搜索次数） | 500，正整数 |
| 分析选点数量 | 3，可设置为 1～3，按引擎推荐顺序取值 |
| 批量分析停止手数 | 20，正整数；当前页面入口限制见下文 |

页面配置保存在 `backend/settings.json`，保存时使用临时文件替换，文件权限为 600，已加入 Git 忽略。密钥不通过配置读取接口返回，也不写入浏览器存储。保存失败不会替换当前运行配置；分析进行时不能修改配置。

AI 接口需兼容当前 DeepSeek 请求协议。模型通过后端环境变量 `DEEPSEEK_MODEL` 配置，默认 `deepseek-flash`，页面不提供模型选择。

### KataGo 接入方式

设置中提供轻量 / 均衡 / 高阶模型档位、安装进度和“保存并测试”。没有安装过 KataGo 也可直接下载安装：Apple 芯片 Mac 下载 KaTrain v1.20.0 内置的 Metal 引擎（要求 macOS 26+），Intel Mac 下载其中的 OpenCL 引擎（macOS 15+），Windows 下载 KataGo 官方 Eigen CPU 包，无需 Homebrew、编译或填写路径。Mac 保留上游应用包及运行依赖，只调用其中引擎，不启动 KaTrain。所有安装文件及模型均按固定大小与 SHA-256 校验，并保存在被 Git 忽略的 `backend/.gogo/`。系统版本不支持时会明确提示。

Mac / Windows 已有 KataGo 时自动复用，只下载并配置模型；已有同名模型通过完整校验后也会复用。后来安装了引擎可点击“重新检测引擎”，手动路径仍位于“高级设置”。下载公共安装文件时沿用环境和系统支持的网络代理，AI 请求方式不变。来源、安装边界与验收结果见 [引擎安装与配置测试](./docs/引擎安装与配置测试.md)。

“保存并测试”先保存配置，再用内置 19 路局面做 32 次搜索，成功后调用一次 AI 解释，分别显示结果和耗时；会产生一次 AI 接口用量，不写入棋谱记录，不修改正式复盘的搜索次数。仅点击“保存配置”仍不调用引擎或 AI。

两种方式由程序与权重路径是否填写决定：

- **本地程序**：同时填写 KataGo 程序和权重的绝对路径。每次分析按需启动独立的 analysis 子进程，使用 [katago-analysis.cfg](./backend/app/katago-analysis.cfg) 固定黑方数值视角，请求结束或超时后释放进程，无需另开 HTTP 引擎服务。
- **本机 HTTP 服务**：两项同时留空。通过 `KATAGO_URL` 连接已有服务，默认 `http://127.0.0.1:8001/analyze`。本项目不管理该服务的启动和关闭。

HTTP 接口必须直接接收 KataGo Analysis JSON、返回结果数组，并配置 `reportAnalysisWinratesAs = BLACK`。仅安装程序或下载权重不能提供 HTTP 服务。更换接口前请按 [接口与字段映射](./docs/接口与字段映射.md) 确认协议，不应仅修改地址后假定兼容。

引擎分析超时为 120 秒，AI 解释超时为 60 秒。保存配置不会启动引擎或请求 AI。

### 环境变量

新机器可在 `backend` 目录复制示例，再填写自己的配置：

```sh
cp .env.example .env
```

| 环境变量 | 用途与默认值 |
| --- | --- |
| `KATAGO_URL` | 本机 HTTP 分析接口，默认 `http://127.0.0.1:8001/analyze` |
| `KATAGO_ENGINE_LABEL` | 引擎展示标识，默认 KataGo 1.17.0 及示例权重名称 |
| `KATAGO_PERSPECTIVE` | 必须为 `BLACK` |
| `KATAGO_VISITS` | 默认搜索次数 500 |
| `DEEPSEEK_API_KEY` | AI 接口密钥，默认空 |
| `DEEPSEEK_MODEL` | AI 模型，默认 `deepseek-flash` |
| `ALLOWED_ORIGINS` | 允许的本机页面来源，默认 `http://127.0.0.1:5178`；多个来源用逗号分隔 |

后端启动时先读取环境配置，再应用 `backend/settings.json` 中保存的页面配置。程序与权重路径未在环境变量中配置，通过页面填写。

## 使用流程

首页“近期对局”仅支持野狐围棋账号查询：输入围棋昵称或用户 ID，点击“查询对局”。结果按时间倒序，每页 10 条，通过“上一页 / 下一页”翻页，可单盘下载原始 SGF，或点击“打开复盘”导入并自动选中棋谱进入分析页。第一页刷新查询，后续页复用后端最多 5 分钟的内存缓存，由 GoGo 后端对已获取的公开列表分页，不承诺全部历史。

下载不会自动导入本地棋谱库。原始棋谱可能存在重复 AP、KM[375]、HA[1] 等与 GoGo 校验不兼容的格式，本功能不猜测转换规则。接口、允许字段及边界见 [棋谱记录查询](./docs/棋谱记录查询.md)。本轮代码修改未运行构建、测试、Lint、类型检查或本地服务。

1. 点击“导入棋谱”，选择 `test.sgf` 或自己的单盘 SGF。根节点缺少规则或贴目、或规则无法识别时，确认信息后才保存。
2. 从历史棋谱进入复盘。使用棋盘下方按钮、左右方向键或手数滑块浏览；Home / End 跳到初始局面或最后一手。第 N 手表示前 N 手已经走完。
3. 点击“分析当前局面”。请求包含初始摆子及前 N 手完整历史。引擎结果先保存，再自动生成中文解释。
4. 查看 A / B / C 候选比较。A 为引擎首选，排序依据是引擎 `order`，不按胜率重新排序。
5. 选择候选后点击“预览变化”，在棋盘查看主要变化；再次点击或按 Esc 退出。解释中的有效坐标支持悬停或聚焦定位。
6. 点击“分析详情”查看完整解释、候选主要变化、目数预测标准差 σ、引擎信息和分析时间。可在详情中“重新生成解释”，无需再次调用 KataGo。
7. 通过“我的棋谱”返回棋谱库。下次在相同浏览器配置和地址打开，可恢复最近棋谱及浏览位置。

页面同时只处理一个分析或解释流程，过程中可以浏览其他步骤或棋谱。迟到结果保存到发起请求时的棋谱和手数，不覆盖其他局面。导入、浏览和恢复缓存不会自动请求分析。重新分析失败保留旧结果；AI 失败保留引擎结果，可单独重试解释。

候选胜率和预计领先目数统一为黑方视角，正领先表示黑方领先，负领先表示白方领先。停一手计入手数，推荐停一手时不在棋盘画坐标。AI 解释用于辅助理解，不作为死活或胜负证明。

### 自由试下

点击棋盘空位，从当前实战局面开始试下，黑白交替落子。支持提子、悔棋和停一手，并检查占位、自杀及立即回提劫。

试下时可点击“分析当前局面”获取临时引擎结果和中文解释，也可预览候选变化。每次落子或悔棋会清除当前试下分析，需重新发起分析。

点击“回到棋盘”或顶部“回到真实棋谱”结束试下。试下着手和分析仅保留在当前页面内存，不修改原始 SGF，不写入实战分析记录，也不会在刷新后恢复。

### 批量分析的当前限制

源码已保留从第 1 手分析至配置停止手数的串行流程，每手完成引擎分析、AI 解释及保存后才进入下一手，失败即停；停止操作在当前手完成后生效，刷新不会自动恢复，重新启动会重新分析指定范围。

**当前棋谱页的“批量分析”弹窗尚未绑定开始按钮**，只能查看已有任务进度或停止任务。设置中的停止手数可保存，但目前无法通过页面发起批量分析。

## SGF 支持范围

- UTF-8（含 BOM），最大 2 MB；支持 9 / 13 / 19 路正方形棋盘。
- 前端使用 `@sabaki/sgf` 解析、`@sabaki/go-board` 处理棋盘，后端用 sgfmill 独立校验。
- 支持根节点 AB / AW / AE（含压缩点列表）、HA、PL、KM、RU，以及主线普通着手、提子和停一手。
- 规则识别支持 Chinese / Japanese，忽略大小写及首尾空白；其他值需手动确认，不猜测规则。
- 中国规则对应 KataGo `chinese`，日本规则对应 `japanese`。两者均禁止自杀、使用简单劫；`chinese-ogs` / `chinese-kgs` 不自动视为同一规则。
- `HA>=2` 时要求实际 AB 数量一致，不补造让子位置。PL 优先，缺失时让子棋轮白，否则轮黑；检查所有主线着手的行棋方。
- 多分支仅浏览第一个分支。原文保留注释和标记，但不作为 AI 分析输入；候选预览与自由试下不提供原始 SGF 分支切换或编辑。
- 拒绝多盘集合、中途摆子 / 规则 / 贴目 / 行棋方 / 尺寸变化、KO 强制非法落子、损坏语法、非法落子及不支持的编码。
- 不提供终局裁判，最后记录的局面仍可主动分析。

## 本地保存与删除

棋谱、最后浏览手数、实战分析和解释保存在当前 Chrome 配置的 IndexedDB。数据库名为 `gogo-review`，schema 版本 1，包含 `games` 和 `analyses` 两个对象仓库。棋谱 ID 为固定键顺序 `{ sgfText, rules, komi }` 的 SHA-256，分析键为 `[gameId, moveIndex]`，不以文件名去重。

协议、主机和端口决定网站来源，`localhost` 与 `127.0.0.1`、不同端口不共享记录。请固定使用 [GoGo](http://127.0.0.1:5178)。浏览已保存结果无需上游引擎或 AI 可用，但仍需前端服务提供页面。

只有事务成功才显示“已保存到本地”。写入失败时保留内存结果并提示重试保存；未成功保存的内容随页面关闭丢失。棋谱页顶部的运行状态入口集中显示存储异常、未保存结果和后台处理状态。

删除需确认，并在同一事务中删除棋谱及关联分析；该棋谱有请求进行时禁用删除。清除浏览器网站数据也会删除棋谱和分析。项目不提供自动备份、跨设备同步、多标签页冲突合并或自动清理旧记录，不持久化进行中的请求，也不会在重新打开后恢复付费调用。

## 常见问题

- **页面打不开或端口被占用**：查看启动终端提示，处理占用 5178 / 8008 的进程后重新启动。
- **无法连接 GoGo 后端**：确认后端已在 `127.0.0.1:8008` 启动；仅启动前端无法发起分析或读取配置。
- **配置提示接口路径或请求方法不正确**：旧后端可能尚未加载配置接口，在原终端停止后重新启动，再点击“重新读取”。
- **KataGo 分析失败**：本地程序模式检查程序和权重绝对路径；HTTP 模式确认已有服务正在运行，并符合接口与 BLACK 视角要求。
- **中文解释失败**：检查 AI 完整 URL、密钥和后端模型配置，在“分析详情”中重试生成解释。
- **历史记录不见了**：确认仍使用同一个 Chrome 配置和 `http://127.0.0.1:5178`，并检查是否清除了网站数据。
