# 首页棋谱记录查询

## 分析页昵称补充（2026-10-31）

按用户确认方案，“打开复盘”将所选列表项已有的 blackName、whiteName 作为可选导入参数传入，连同规则、贴目确认流程一起保留，成功后保存为 GameRecord 的可选同名字段。取消导入不保存；相同棋谱重复导入补充列表昵称，保留原浏览位置和分析。

分析页黑白昵称逐方按“已保存的非空列表昵称 → SGF 根节点 PB/PW → 未提供昵称”显示。PB/PW 仅作棋手名展示；不查询额外账号接口、不使用其他别名、不修改原始 SGF 或棋谱标识，也不发送昵称给 AI。下载接口和列表接口的请求响应保持不变。

依据：2026-10-31 用户要求在首页按平台、账号查询近期下棋记录，每页 10 条。

平台仅提供野狐围棋（fox），查询和单盘下载均使用下文明确的野狐接口。

野狐来源：[开源接口实现](https://github.com/wimi321/GoAgent/blob/main/src/main/services/fox.ts)，以及本次会话对账号 33872676、500280588 的真实响应。两个账号在野狐来源分别返回 57、30 盘，已逐盘下载和核对。这些结果只表示当次可查询的公开记录，不承诺全部历史，也不代表本次页面修改经过运行验证。

## 实现前允许字段清单

### 野狐账号查询

GET https://newframe.foxwq.com/cgi/QueryUserInfoPanel

请求仅使用 srcuid=0、username=输入昵称。响应仅使用 result、uid、username，其中 uid 为数字字符串。非零 result 不取任何备用字段。

输入为纯 ASCII 数字时直接作为 UID 查询列表，不将其当作昵称。名称缺失时显示 ID，不猜测其他账号字段。

### 野狐记录列表

GET https://h5.foxwq.com/yehuDiamond/chessbook_local/YHWQFetchChessList

固定参数为 srcuid=0、dstuid=目标 UID、type=1、lastcode=0、searchkey=空字符串、uin=目标 UID。响应只读取 result、chesslist。

| 业务含义 | 允许的列表项字段 | 规则 |
| --- | --- | --- |
| 棋谱标识 | chessid | 数字字符串，完整保留，不转 JS number |
| 账号归属 | blackuid、whiteuid | 整数，仅保留包含目标 UID 的记录 |
| 黑白棋手 | blacknick、whitenick | 原文显示，不使用其他名称别名 |
| 下棋时间 | starttime | 原样显示 YYYY-MM-DD HH:mm:ss |
| 排序依据 | gamestarttime | 秒级时间戳的数字字符串，按数值倒序 |
| 棋盘尺寸 | boardsize | 正整数，显示为“X 路” |
| 着手数 | movenum | 非负整数，显示为“X 手” |
| 胜负 | winner | 1 黑胜、2 白胜；结合 blackuid / whiteuid 转为查询账号的胜 / 负；其他值显示“未标注” |

数字 ID 查询时，账号名只取最新记录中目标 UID 对应一方的 blacknick 或 whitenick；无记录时为 null。昵称查询使用账号接口的 username。

不读取总胜负推断列表完整性，不增加分数、段位、贴目、规则字段或别名。

### 野狐单盘下载

GET https://h5.foxwq.com/yehuDiamond/chessbook_local/YHWQFetchChess

请求仅含 chessid。响应仅使用 result、chessid、chess。校验返回 ID 一致、chess 为以游戏树开始的非空字符串，UTF-8 大小不超过 2 MB。直接下载原始内容，不转换 KM，不修改 HA，不合并 AP。

## GoGo 内部接口

### 重复 AP 的导入兼容（2026-10-31）

依据本次“打开复盘”报错修复，仅允许 `AP` 在同一节点重复。允许字段清单：生成软件信息只使用 `AP`，含义来自 [SGF FF[4] 的 AP 定义](https://red-bean.com/sgf/properties.html#AP)，没有别名或回退字段。重复容忍是 GoGo 的导入兼容策略，不代表标准允许重复属性。

前端导入与后端分析复验采用相同策略：允许解析库收集重复 `AP` 的值，不选择或推断其中某一项。`AP` 不直接作为棋盘、规则或分析输入，仅按下节明确约定识别野狐贴目特例。原始 SGF 的下载、存储和标识计算保持原文；不删改或重写 `AP`。其他重复属性仍拒绝，`AP` 缺少方括号值等语法错误仍拒绝。

### 野狐贴目与默认规则（2026-10-31）

本次贴目报错修复的允许字段仅为根节点 `AP`、`KM`，规则默认值沿用已有 `chinese`。依据 [Sabaki SGF 问题 #11](https://github.com/SabakiHQ/sgf/issues/11) 的 `375 → 7.5` 记录，以及 [KaTrain 解析实现](https://github.com/sanderland/katrain/blob/485b55c42df4dd1c77abf21eefc23c9a17d6a512/katrain/core/sgf_parser.py#L388-L396) 使用 `AP` 值列表中的精确 `foxwq` 标识识别来源。

前后端只在根节点 `AP` 值列表包含精确字符串 `foxwq`、且合法数字格式的 `KM` 数值为 375 时，将有效贴目解释为 7.5。原始 SGF 下载、存储和标识计算保持原文，不改写 KM。普通棋谱继续按 SGF 标准读取 KM；不将所有贴目除以 50，不添加其他数值或来源别名，不根据规则、让子数猜测贴目。其他非法 KM 仍拒绝。

按用户要求，规则缺失或无法识别时，导入确认框默认选中中国规则，用户仍可改为日本规则并确认；棋谱中已识别的规则保持不变。缺失贴目仍需填写。

内部字段由本次页面需求定义，与上述上游字段一一映射，无猜测回退。额外请求字段拒绝；错误沿用 `{ code, message }`，不透出上游原文或堆栈。

### POST /api/records/query

请求仅含 platform（固定 fox）、account（去除两端空白后的非空昵称或 ID，最多 64 字符）、page（从 1 开始的整数）。pageSize 固定为 10，不接受自定义大小。

响应只含 platform（fox）、accountId（字符串）、accountName（字符串或 null）、page、pageSize（10）、total（本次获取的记录数）、items。

items 每项只含 chessId、playedAt、blackName、whiteName、boardSize、moveCount、result（win / loss / unknown）。对应 chessid、starttime、blacknick、whitenick、boardsize、movenum 和由 winner / UID 明确计算的胜负。

野狐上游 GET 请求尚无可靠分页证据，本地服务取得列表后按 gamestarttime 倒序、按 chessid 去重，再切为每页 10 条。page=1 主动刷新上游；后续页复用最多 5 分钟的内存缓存，缓存缺失或过期重新获取。最多缓存 20 组平台 / 账号查询，不持久化。超出页数返回明确错误。

total 只表示上游本次可查询的记录数，不承诺全部历史。

### POST /api/records/sgf

请求仅含 platform（固定 fox）、chessId（1～32 位数字字符串）。响应仅含 chessId、sgfText。“下载 SGF”以 chessId.sgf 下载 UTF-8 文件；“打开复盘”将同一响应交给现有 SGF 导入流程，不新增接口或字段，不自动发起 AI 分析。

## 页面行为

首页显示“近期对局”表单，手动点击查询才发请求。每页至多 10 条，显示日期、黑白棋手、查询账号胜负、路数与手数，棋谱栏提供“打开复盘”和“下载 SGF”，并支持上一页 / 下一页。修改平台或账号后清除旧查询；查询、下载或打开期间禁用表单、翻页及棋谱操作，错误保留已显示的记录供重试。离开首页后不使用迟到的棋谱获取响应触发导入。

### 浏览器列表缓存（2026-10-31）

依据用户要求“用户不点查询时回显上一次的结果”，使用 localStorage 的 `gogo-records-last-query` 保存最后一次成功查询（含翻页）的单页结果，不设置自动过期或后台刷新。

新增本地缓存允许字段仅为 `account`（本次请求去除首尾空白后的账号）和 `records`（完整复用 `OnlineRecordsPage`：platform、accountId、accountName、page、pageSize、total、items，列表项字段沿用上文内部接口）。不缓存 SGF、加载状态或错误，不新增服务端字段或别名。

每次进入首页先恢复已有表单，再优先回显有效缓存对应的查询账号、平台、页码及列表，包括空结果；未提交的表单修改不会覆盖上一次成功查询。恢复不请求接口。修改表单后仍清除当前显示的列表，保留成功缓存供下次进入时回显。点击“查询对局”请求第一页，点击上一页 / 下一页请求目标页，成功后替换缓存；失败保留先前成功结果。缓存损坏或字段不符合契约时忽略；浏览器存储不可用或写入失败不阻断正常查询。

依据用户新增要求，“打开复盘”复用本地导入的解析、存储和去重逻辑，成功后自动选中棋谱并进入分析页；相同棋谱恢复已有浏览位置。规则或贴目缺失时沿用确认弹窗，确认并导入后进入分析页，取消则留在首页。重复 `AP` 和野狐 `KM[375]` 按上文兼容策略导入；当前上游原始 SGF 与 GoGo 的让子、其他贴目及重复属性校验仍存在兼容差异，解析失败保留当前棋谱并提示原因，不猜测转换字段，不自动运行引擎或 AI。
