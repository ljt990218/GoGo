## 指定候选点解释（2026-10-31）

依据用户确认：新增内部字段统一为 `candidateIndex`，0 / 1 / 2 分别对应引擎原始顺序的 A / B / C，不重排、不截取候选列表，不重新调用 KataGo，也不落子。本节替代下文关于解释请求、响应和存储不新增字段的旧约定，其余字段约束保持不变。

| 业务含义 | 允许字段 | 约定 |
| --- | --- | --- |
| 解释目标 | ExplainRequest.candidateIndex | 严格整数，0～2，必须小于 analysis.candidates.length；省略明确按 0 处理，保留默认解释 A 的流程 |
| AI 输入目标 | 结构化上下文 candidateIndex | 与请求相同，索引原始 candidates，提示词围绕该选点解释，不把 B / C 改称引擎首选 |
| 返回解释归属 | ExplanationResult.candidateIndex | 必填，与请求目标一致；原 explanation、aiModel、explainedAt 保持不变 |
| 保存解释归属 | AnalysisRecord.candidateIndex | 与解释一起保存；旧记录缺失时明确按 A（0）处理，不猜测正文中的坐标 |

IndexedDB 升级到版本 2，仅为旧 analyses 记录补 candidateIndex=0，保留原记录和主键。引擎结果尚无解释时新记录的 candidateIndex=0。每个局面仍保存一份最近成功的解释及其归属，不新增多选点缓存。

B、C 坐标后均提供“分析此点”，点击时选中该点并只生成其解释；解释属于其他候选时，选中 A 也提供该入口。切换选中项不自动请求、不改动已有解释的归属。进行中禁止重复提交，失败保留原解释；响应按请求时的局面和 candidateIndex 归属，不跟随随后切换的选中项。上方“重新分析”仍重新分析当前整个局面，默认生成 A 的解释。

### 下载入口修正（2026-10-30）

本补充优先于下文仅允许配套包的限制：有可执行的本机 KataGo 时复用现有引擎，不再因平台包缺失而禁用模型下载。无本机引擎时才要求平台包完整。全新 Mac 的配套包仍未提供，不假装支持全新机器的一键安装。

- 本机引擎检测顺序明确为：已保存的 katagoPath、PATH 中的 katago、Mac 对应 Homebrew 的 /opt/homebrew/bin/katago（arm64）或 /usr/local/bin/katago（x64）。只接受绝对路径、实际文件和可执行权限，不搜索其他应用或猜测文件名。
- 本机现成模型只检查已保存的 katagoModelPath，以及 Mac 对应 Homebrew 的 share/katago 下与官方 URL 文件名完全相同的文件；与官方 size、sha256 一致才可复制复用，否则从固定官方 URL 下载。
- installedTier：当权重路径对应受管目录中的固定模型、引擎文件可执行时返回档位；复用本机引擎同样适用。受管引擎显示清单版本；复用引擎只显示“KataGo · 模型名称（本机引擎）”，不猜测版本或 CPU/GPU 后端。
- options[].message 允许在 available=true 时说明“已找到本机引擎，将复用并下载模型”，前端始终展示非空说明；available 由“模型信息齐全，且本机引擎存在或平台包齐全”决定。
- 模型元数据来源：官方 `https://katagotraining.org/api/networks/{完整模型名称}/`。允许字段仅 name、model_file、model_file_bytes、model_file_sha256，分别映射 name、url、size、sha256。字段依据为 KataGo 官方 `python/upload_model.py` 及三个模型的真实 API 响应；清单固定存储查询所得值，运行时不猜测字段或访问动态列表。
- Windows 包信息来源：GitHub `repos/lightvector/KataGo/releases/tags/v1.18.1` 的 assets，仅读取 name、browser_download_url、size、digest，精确选择 `katago-v1.18.1-eigen-windows-x64.zip`；digest 只接受 `sha256:` 前缀，去掉前缀后登记清单。不使用 AVX2 专用包，不引入其他字段回退。
- 本机文件与远端文件均在点击下载安装后才做完整 SHA-256 校验，浏览设置只做文件存在性与执行权限检查，不启动引擎。来源查询和文件读取不等同于运行项目验收，本次仍不执行项目测试或服务。

所有接口为 POST，空请求为 `{}`，遵循现有 `{ code, message }` 错误约定。

## 分析交互补充（2026-10-29）

依据最新需求：棋盘候选标记保留 A/B/C，依次展示字母、blackWinRate 胜率和当前行棋方视角的目差。棋盘胜率使用 blackWinRate，toPlay 为 black 时显示 blackWinRate × 100%，为 white 时显示 (1 − blackWinRate) × 100%，保留一位小数；目差仅使用 blackScoreLead（上游 moveInfos[].scoreLead），toPlay 为 black 时原样展示，为 white 时取反，保留一位小数和“目”单位，不显示正数加号。示例：白方行棋，黑方领先 -1.7 / -0.2 / 0.3 目，棋盘对应显示 1.7 / 0.2 / -0.3 目。展示转换不修改存储及 AI 输入中的原始黑方数值。侧栏表格仍明确标注黑方胜率、黑方领先。

scoreStdev 仅在侧栏胜率下显示 σ。根据上述 KataGo 1.17.0 官方文档，它是最终目数的预测标准差，受 MCTS 影响可能偏高，不是胜率置信区间，也不是目差。新分析必须读取 moveInfos[].scoreStdev。内部 Candidate 的 scoreStdev 为非负有限 number；现存已保存记录没有该字段，允许缺失或 null，显示“标准差未提供”，不推算、不补零，重新分析可获取。

自然语言中的有效 GTP 坐标按当前棋盘尺寸识别并高亮；悬停或聚焦可定位。主要变化仅使用 principalVariation，首手立即显示，随后每隔 250ms 推进一步；停一手计入步数和行棋方轮换，提子按现有规则库处理。预览不写入棋谱或存储，离开、失焦、切换局面和分析更新时清除。
